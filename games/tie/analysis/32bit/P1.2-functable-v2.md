## Method
Anchor-driven linear extraction to fixpoint + step-1 orphan prologue scan:
1. Candidates: hard anchors + v1 starts + near call/jmp targets (E8/E9, capstone
   absolute) + near [disp] targets resolved against runtime base 0x7E000 + orphan
   scan at prologue-like first bytes (55/53/56/57/50-54/8B/8D/89/9C).
2. Extract = linear disasm with stack-balance tracking (push/pop ±4, 16-bit word
   push/pop via 0x66 ±2, push/pop dword [reg] 0x60-0x63, add/sub esp ±imm,
   mov-esp→bal=0, lea-esp→unknown).
3. Function end: `ret`/`ret imm16`/`retf` with clean balance (bal%4==0; positive
   balance = locals not popped on the linear path — early returns; `ret imm` also
   accepted at exact arg-cleanup balance), or forward tail-`jmp` at bal==0 (CRT
   transition blocks, entry region 0x3F002..0x3F48F).
4. Overlap-safe adoption (range-overlap check both passes); string regions
   (rizin strings, len≥12) excluded from orphan starts.

(≥ 0x0E6008, 0x0EE9C3, and the 0x0BA5xx-0x0BA8xx cluster — `8c d0 8e e8` segment ops,

/thunk bodies the loader transitions through; a pure 32-bit sweep cannot classify them.
They fall to P1.4 (16-bit sweep) + P1.1 (DOS4GW disassembly for the transition model).

## Notes / corrections
- **0xAAE83 is not a function start** (docs' "C-CRT main anchor"). Bytes there =
  `e8 71 56 01 00` (mid-function call). The true function spans **0xAAD94..0xAB0A1**
  (781 B) — the large CRT/scene-init main; 0xAAE83 sits inside it.
- v1 "missing" starts, classified: 736 were false rizin "strings" (push-opcode runs
  like `53 51 52 56 57 55` = "SQRVWU" — fixed by min-length 12), remainder:
  ret-balance early-return functions (477), 2-3 v1 artifacts at trailing-`ret`
  addresses (0x04D7B0, 0x05BFF0, 0x05F940, 0x0C336C), 2 mid-function anchors
  (0x09727C/0x0978B5 = `push 0xe4; call …` tails), 2 data false-positives
  (0x0F39EE, 0x0F46DC).
- Known limitation: linear-scan truncates at the first clean `ret` (early-return
  paths); function bodies after such a ret are left as separate v2 functions or
  uncovered. Acceptable for coverage/naming; CFG-accurate boundaries need P1.3
  (Ghidra) on hot paths.
- Capstone 5.0.7 quirks handled: no `CS_REG_ESP` export (numeric 30), instruction
  start = `i.address` (not `.start`), `i.bytes[0]` is int (never slice-compare).
