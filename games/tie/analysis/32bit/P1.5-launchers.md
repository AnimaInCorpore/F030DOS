## TIE.EXE (31,568 B) — a plain 16-bit Watcom program

✗ **Withdrawn (2026-08-21): "a DOS4G hybrid, not a plain 16-bit launcher."**
Re-measured with `python work/audit_headers.py game/SWTieCD/TIECD/TIE.EXE`
(assumption-free): the MZ image `(e_cp−1)·512 + e_cblp = (62−1)·512 + 336 =`
**31,568 = the whole file**; entry `e_ip`@0x14 = `0x0D8C`, `e_cs`@0x16 = 0 →
file **0x110C** = `E9 A4 00` + `WATCOM C/C++16 Run-Time system` — the Watcom
16-bit CRT, executing under plain DOS like any MZ program. There is no 32-bit
image and no container mystery. The withdrawn readings, each quoted:

- *"8-entry pointer table @ 0x20: `0x3567 0x37E5 0x37BC 0x395C 0x3926 0x38FF
  0x38DA 0x39EC` … 16-bit code entry points"* — `e_lfarlc` = **0x20**, so
  file 0x20..0x378 is the **relocation table** (214 × `(offset u16, segment
  u16)`, 214/214 targets inside the image). The eight dwords are the first
  eight relocation entries; they "verified as code" because relocation
  targets point *into* instructions (at segment operands) by design.
- *"`e_lfanew` = 0x39EC → 32-bit image start"* — with `e_lfarlc` = 0x20 the
  dword @0x3C is **relocation data**, not `e_lfanew` — the family's MZ-fields
  trap in its purest form (`cross-project.md` §1).
- *"32-bit image 0x39EC–0x7B30 (163 fns swept, 54.3 % code)"* — a 32-bit
  sweep over ordinary 16-bit Watcom code and data; the "functions" are the
  wrong-bitness decode the family's `ndisasm -u` trap warns about, in sweep
  form. `32bit_TieExe.txt` / `tie32.txt` are void.
- *"16-bit entry stub @ 0x395C"* / *"e_ip=0x0020"* — field misreads
  (`e_ip=0x20` was `e_lfarlc`; the real entry is 0000:0D8C).

What survives, and mattered: the **string pool 0x71C2–0x7814 is real**
(strings are encoding-agnostic) — the launcher sequence, `detvesa`,
`dos4gw`, `/trebla`, `z_tie2__.exe` and the SciTech UNIVBE prompt block all
stand, and with them the corrected boot chain below. `16bit_TieExe.txt` (110
fns over 0x40..0x395B) remains valid as far as it went but stopped short:
the 16-bit program continues to the end of the file.

**`/trebla` resolved**: anti-double-launch marker token passed TIE.EXE → Z_TIE2__ →
Z_TIE__ (same check inside the game image, `You must run TIE.EXE for the game.\n`
@ img+0x0A981A). "trebla" = LucasArts-internal codename; purpose was TBD in
`DOS4G-header.md` — now answered. `/320` = resolution selection (320×200).
