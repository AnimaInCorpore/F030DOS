# sub_00048105 — viewport bounds setter

Status: `Verified` for the isolated function contract in JavaScript and m68k;
connected game support remains open. Canonical DOS ID
`sub_00048105`, LE object 1 vaddr `0x48105..0x48174`, file
`0x903A9..0x90418`, end exclusive. Unpatched PANZER.EXE SHA-256
`115ada29636b32c3e07446fdf4569d97324d357a1e71dafb859dd95c3cb69a86`.
Runtime placement: vaddr + `0x16D000`; inventory `work/re/functions.txt`.

## Contract and DOS evidence

No callees. Inputs EAX, EDX, EBX and ECX supply four bounds. Only their low
16 bits are used, zero-extended. The fifth stack argument's low byte selects
one 20-byte record. Four LE dwords are written at object-2
`0xC620 + index*20`, in input-register order; the four preceding bytes at
`0xC61C + index*20` are retained. EAX returns `index*20`; EDX returns ECX's
low word zero-extended. EBX, ECX, ESI, EDI and EBP are preserved. `ret 4`
consumes the stack index argument. No checks/clamps, files or hardware access.

`tests/fixtures/dos-geometry.json` contains one connected menu-to-Poland route
call and four isolated executions of the unchanged DOS function. Cases cover
upper register bits, index 255 and a stack index with nonzero upper bytes.
Only the low byte selects the row. The probe restores all injected memory and
CPU state before resuming the connected game; isolation is not route closure.
The loader calls this function at `0x3808D`; other UI callers also use it.

## Implementations and differences

- JavaScript: `sub_00048105`, `web/reference/geometry.mjs`.
- m68k: `sub_00048105`, `src/common/geometry.s`; explicit ABI in source.
- m68k, generated: `x86_sub_00048105` (keeps the DOS `ret 4` stack argument,
  pushed little-endian by the shim `sub_00048105`) from `tools/x86x/translate.py`
  (`analysis/x86-translation.md`); passes the same 12 geometry fixtures and the
  loader fixture (`--translated`, 2026-10-06).
- Object-2 memory is a byte arena; bounds/index are explicit values rather
  than x86 registers and stack. Native register ownership and ordinary RTS
  replace the DOS stack convention. These target representation/ABI changes
  retain the same memory/return-value fixtures.
- Native LE stores are assembled explicitly. Upper halves are zeroed exactly
  as DOS does, rather than preserving high input bits.
- CPU flags/dead stack locals differ and are outside this caller-visible
  contract. No hardware adapter or semantic substitution occurs in the body.

## Support gate and open work

Fixture parity is required before native use. Viewport storage initialization,
loader bounds production and display-driver consumers remain unresolved for a
connected playable slice. Commands/status are in `docs/PORTING-PLAN.md`.

and in the native Hatari contract harness. Native arena allocation is word
aligned, matching the original DOS object placement. Physical Falcon and full
game integration remain unverified.
