# Evidence-carrying disassembly seeds for the hash-identified IndyCar Racing
# executable. Add a seed only after the executable/container and address model
# are established; cite the evidence in analysis/ beside each addition.

# analysis/executable.md, measured 2026-08-26 with a whole-RAM dump at the
# copy-protection prompt: the image is not one flat span. Code in the block
# that spans the LE-page/appended boundary maps at file = runtime - 0x13EEDC,
# and that module's data at file = runtime - 0x13FEDC -- one page apart, so a
# code delta must not be used to resolve a data address.
CODE_DELTA runtime_minus_file=0x0013eedc range_file=0x00050400..0x000b4400
DATA_DELTA runtime_minus_file=0x0013fedc range_file=0x000a1124..

# analysis/executable.md: the LE object page map is the identity and the page
# size is 0x1000, so file = vaddr + 0x1A400 across both objects.
LE_PAGEMAP file_minus_vaddr=0x0001a400 vaddr=0x00010000..0x00076000

# analysis/executable.md "Declared entrypoint": NOT a seed yet. The LE EIP
# field reads as object-relative (ESP = object 2's virtual size exactly),
# giving vaddr 0x5D254 = file 0x77654; the previously recorded file 0x67654 is
# the other reading. Neither lands on a function boundary and the image is not
# loaded at its declared object bases, so no entrypoint seed is asserted here.
